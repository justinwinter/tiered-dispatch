The problem

Your agent picks one model per session — and defaults to the expensive one for everything.

Claude Code, Codex, Cursor, Copilot let you set a model once per session. That session handles trivial mechanical work on the same tier as genuinely hard reasoning. One Claude Code Max subscriber's self-reported usage showed 93.8% of their tokens going to the top-tier model — with nothing pulling cheap work back down. One user's numbers, not an industry audit; the open GitHub issue's engagement suggests the pattern isn't unique.

The obvious fix doesn't work

Ask the model how confident it is, and route on that. But LLM self-reported confidence is poorly calibrated — a model that's wrong is often just as “confident” as one that's right. A threshold buys the feeling of a safety check without the substance.

Undercut replaces “confidence” with three objective triggers: a failed verification, a measured disagreement between two cheap-tier runs, or an explicit uncertainty flag. Nothing ever escalates on a vibe.

How it works

Six flags assign a tier. Three triggers are the only way up.

Every unit of work is scored against six flags, then assigned the cheapest tier that can plausibly handle it. It only moves up a tier when something objective proves it needs to — a failed check, a measured disagreement, an explicit uncertainty flag. It never moves up on a guess, and it never moves back down mid-task. See the rubric.

Step 1 — Base tier, six-flag rubric
  • Unverifiable can output be checked mechanically? tests, schema, diff, grep
  • Ambiguous one right answer, or several defensible ones?
  • Blast reversible? touches money, auth, user data, production, deletes?
  • Cross-cutting one file/source, or reasoning across many?
  • Novel pattern-following, or genuinely new design?
  • Format-strict must it match an exact schema?

0 flags → cheap. 1–2 → standard. 3+ or any ownership/judgment call → frontier. Apex only when you can write one sentence stating why the marginal intelligence pays for the cost.

The override (biggest lever): “cheap-to-verify ⇒ cheap-to-generate.” If output can be mechanically checked, start at the lowest tier no matter how hard it looks — verification catches failure.

Step 2 — Escalate one tier, on evidence only
  • Verify ×2 verification fails twice at the current tier
  • Disagree an ambiguous work gets two cheap-tier runs that differ
  • Uncertain the worker tagged it unsupported/uncertain

Residue-only: the next tier gets only the failed/uncertain items plus verification notes. It resolves the residue; it never redoes the batch.

Hysteresis & the batched apex tie-break

Never de-escalate mid-task. Max one retry per tier. Anything still unresolved goes to a single batched apex tie-break call. One hard file in a 700-file job doesn't drag the other 699 up a tier.

Why it holds up

Flags steer. Verification and escalation decide.

What this doesn't do.

  • Not a proxy Doesn't enforce anything at the network layer.
  • Not a gateway Composes with compression proxies: routes first, they compress second.
  • No auto-flagging The dispatching agent scores the flags itself. Measured robust to wrong flags.
  • No savings on a tier without capability OpenAI + Python is the documented case — no headroom, quality still held.
  • Not a planner Planning is separate from execution routing; this ladder handles execution units.

Prior art

Others have tried cheaper-model routing.

peragwin's subagent-model-routing gist and soumabali/token-router both explored assigning cheaper models to subagent work. Undercut adds the objective escalation loop: measured disagreement instead of self-confidence, hysteresis so a run can't thrash between tiers, residue-only escalation, a calibration loop — and, the rare part, published reproducible A/B results anyone can re-verify.

Not competing with your gateway

Compression proxies shrink what goes over the wire. Undercut decides which model handles the call in the first place. Route first, compress second — they stack.

FAQ

Real answers to real objections.

Does this replace choosing a model per session?
No. It runs inside a session, per unit of work, underneath whatever top-level model choice you've made.
What if I'm on an open-weight model?
Check your tier pricing first: some ladders invert, which flips the cost math (quality still holds). See the caveat in the benchmarks section.
Do I need to build a custom flagging model?
No. Stock dispatchers (Haiku, Sonnet) hit 90%+ flag accuracy and 100% tier-match under the shipped policy.
Does this go stale when a new model ships?
The routing rules are about work properties, not models. The tier-to-model mapping is versioned separately and updates on its own cadence.
Does this touch our network or data?
No. It's a policy file the agent reads locally. Nothing proxies traffic, nothing calls home.
